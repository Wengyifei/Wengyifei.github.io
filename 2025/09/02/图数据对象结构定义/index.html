图数据对象结构定义

图数据对象 (Data Object) 结构定义书

文档目的:

本文档为项目团队（王璇、翁怡菲、汪雨菲）提供统一的、标准化的图数据格式定义。所有数据处理、模型输入和模型输出的衔接工作，必须严格遵守本合同规定，以确保项目的模块化、可复现性和高效协作。

核心数据:

  • 主要数据: 信噪比 (SNR), 反射率 (Reflectivity)，反射率（brsc）
  • 辅助数据: 植被指数 (NDVI), 地形数据 (DEM)
  • 标签数据: SMAP标准土壤湿度
  • 坐标系: WGS 84 (EPSG:4326)

第1部分: 原始数据与预处理标准

1.1. 统一栅格化标准:

* 目标坐标系: WGS 84 (EPSG:4326)。

* 目标分辨率: [0.08度 x 0.08 度]。
* 空间范围 (Bounding Box):纬度：南纬40-北纬40，经度：西经180-东经180
* NoData 值: 所有栅格文件中，无数据区域统一使用 -9999.0 作为标记值。

第2部分: PyTorch Geometric Data 对象结构

项目将整个研究区域构建为一个单一的 torch_geometric.data.Data 对象。该对象包含以下属性：

2.1 data.x (节点特征矩阵)

  • 用途: 存储每个网格单元（节点）的输入特征。
  • 形状: [N, 5]
    • N: 研究区域网格总数 (height * width)。
    • 5: 特征数量。
  • 数据类型: torch.float32
  • 标准化: 所有特征在存入 data.x 前，必须进行 Z-score 标准化（减去均值，除以标准差）。每个通道独立计算其均值和标准差。NoData 值不参与计算。
  • 通道顺序 (固定):
    • x[:, 0]: 反射率 (Reflectivity)
    • x[:, 1]: 信噪比 (SNR)
    • x[:, 2]: 反射率 (BRCS)
    • x[:, 3]: 地形高程 (DEM)
    • x[:, 4]: 植被指数 (NVID)
  • 处理 NoData: 原始数据中的 -9999.0 在标准化后，统一用 0.0 填充。因为Z-score标准化后，数据的均值为0，用0填充对数据分布的影响最小。

2.2 data.y (节点标签向量)

  • 用途: 存储SMAP标准土壤湿度真值。
  • 形状: [N, 1]
  • 数据类型: torch.float32
  • 内容:
    • 对于有SMAP数据的网格，填充真实的土壤湿度值。
    • 对于没有SMAP数据的网格，填充 float(‘nan’)。
  • 注意: 标签数据 y 不进行 Z-score标准化，保留其原始物理意义。

2.3 data.pos (节点地理坐标)

  • 用途: 存储每个节点的经纬度坐标，用于图构建和可视化。
  • 形状: [N, 2]
  • 数据类型: torch.float32
  • 内容与顺序 (固定):
    • pos[:, 0]: 经度 (Longitude)
    • pos[:, 1]: 纬度 (Latitude)

2.4 data.edge_index (图连接性)

  • 用途: 定义节点之间的空间关系。
  • 形状: [2, E] (E 为边的总数)。
  • 数据类型: torch.int64
  • 构建策略:**8-**邻接图。每个节点与其周围的8个邻居连接。

· 格式: 必须为无向图，即每条边(u, v)需同时存储(v, u)。

2.5 data.edge_attr (边属性)

  • 用途: 存储每条边的附加信息/权重。
  • 形状: [E, 1]
  • 数据类型: torch.float32
  • 内容 (与edge_index一一对应):
    • edge_attr[:, 0]: 地理距离的倒数。计算edge_index中每条边连接的两个节点间的Haversine距离d，属性值为1 / (d + 1e-6)（加一个小常数防止除以零）。

2.6 节点掩码 (train_mask, val_mask, test_mask)

  • 用途: 将有标签的节点划分为训练、验证和测试集。
  • 形状: 均为 [N]。
  • 数据类型: torch.bool
  • 构建方法:
    1. 找出所有data.y中非nan值的节点索引，构成“有标签节点集 L”。
    2. 将 L 按 80% : 10% : 10% 的比例随机划分为训练、验证、测试索引。
    3. 根据划分的索引，填充三个布尔掩码。所有无标签节点的掩码值均为False。

2.7文件命名：

Day200601_Graph.pt ; Day230201_Graph.pt ；……（年+月+日）

第3部分: 模型接口标准

3.1 ESA 输出 -> U-Net 输入 接口

  • **文件格式: **GeoTIFF (.tif)
  • 文件规范:
    • 坐标系与栅格: 与第1部分定义的“统一栅格化标准”完全一致：WGS 84 (EPSG:4326)。
    • 数据内容:
      • 土壤湿度结果被重塑为一个二维矩阵 (100 x 450)。
      • 矩阵中每个像素的值是对应节点的ESA预测土壤湿度。
    • NoData 值: 文件中必须正确设置NoData值为 -9999.0，此阶段不再使NaN。
    • 命名约定: SM_ESA200601.tif ; SM_ESA230201.tif ; …… （年+月+日）

3.2 U-Net端：

  • 读取此GeoTIFF文件。
  • 将NoData值（-9999.0）的像素替换为0.0。
  • 将此处理后的矩阵作为U-Net输入的一个通道。
